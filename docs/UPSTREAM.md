# 我们的 UI 分支（`vendor/upstream/`）

**这份代码是我们的。** 它最初是 MIT 许可的
[`JohnnyZ93/pi-agent-studio`](https://github.com/JohnnyZ93/pi-agent-studio) VS Code 扩展在 tag
`v1.3.8` 的一个子集副本，**现在由本项目维护**：像 `src/` 下的代码一样，随便改。

它提供聊天 UI（`pi-chat/`）与内置的 pi 扩展（`bridge/`）。

两件需要说清的事：

- **没有任何东西要求我们与任何上游版本一致。** 这里曾经有一条 CI 作业会克隆上游 tag、
  字节有差异就判失败；那条作业已经删掉，`scripts/check-upstream.cjs` 也一并删除。
  现在 CI 与构建**完全不访问** `pi-agent-studio` —— 上游发新版**不会**让我们的 CI 变红 ✓。
- **上游仍是我们要主动吸收的源**，但不是强制的：想要它的新东西时，按下面
  「主动吸收上游」的流程取，取多少、取哪部分由我们决定 ✓。

## 我们从上游保留了什么（以及丢掉了什么）

保留 —— 应用真正会加载的东西：

| Path | Why |
| --- | --- |
| `pi-chat/` | single-file chat UI; source is needed for `npm run build:renderer` |
| `bridge/` | `todo`, `questionnaire`, `btw`, `permission-gate`, `rewind-code`, `subagent`, `mcp`, `agents/*.md` |
| `pi-mcp/` | source of the bundled MCP extension (`bridge/mcp/index.js`) |
| `assets/` | tray icon fallback (`icon.png`) |
| `LICENSE`, `CHANGELOG.md`, `package.json` | provenance + version record |

Stripped (upstream VS Code extension plumbing the standalone app never touches:
`.github/`, `.vscode/`, `.pi/`, `.agents/`, `src/` (53 files), `pi-settings/`,
`l10n/`, `test/`, `scripts/`, `rolldown.config.ts`, `tsconfig.json`, `pnpm-*`,
`package.nls*.json`, `typecheck.sh`). The vendored tree went from 155 tracked
files down to 56.

## 我们相对分叉点做过的改动

这份清单现在只用来记录“我们改了什么” ✓（因为我们已经拥有这份代码，不再需要为了对齐上游
而把改动限制在允许列表里 ✓）。

1. **`bridge/mcp/index.js` — build output that is tracked on purpose.** The app
   loads it directly (`-e <bridge>/mcp/index.js`) when `mcpEnabled` is true, so it
   ships prebuilt. It is produced from the vendored source by:

   ```bash
   npm run build:mcp   # cd vendor/upstream/pi-mcp && npm install && npm run build
   ```

   `pi-mcp/rolldown.config.ts` writes to `../bridge/mcp/index.js`. The bundle is
   newer than the MCP source in the upstream v1.3.8 tag, so rebuild (and re-run
   the smoke test) whenever either side changes.
2. `pi-chat/package-lock.json` — produced by `npm install` inside the vendored
   dir (gitignored).
3. `pi-chat/src/model-icons-data.ts` — generated by
   `pi-chat/scripts/extract-model-icons.mjs` (gitignored).

除上面几条外，目前没有改动过其它文件：应用侧的适配全部发生在
`src/main/chat-adapter.ts`（HTML 注入 + `acquireVsCodeApi` shim）。

**注意：这条不再是约束。** 我们现在拥有这棵树，可以像改 `src/` 一样直接改它 ——
代价只是将来想吸收上游同一处的改动时要自己合并一下。真正需要盯的不是“有没有改过”，
而是下面的契约：注入层依赖上游 DOM 里的少数几个钩子（输入框、消息气泡、重排用的容器），
一旦上游改名，症状会是**界面照常、功能静默失效**。吸收新版时先跑
`npm run test:daily`，它才是能接住这类问题的那一道。

## Not tracked / must be rebuilt

- `vendor/upstream/pi-chat/dist/index.html` — the 5.7 MB single-file UI bundle is
  **gitignored**. A fresh clone must run `npm run build:renderer`
  (needs network: it runs `npm install` inside `vendor/upstream/pi-chat`) before
  the app can show a chat UI. Without it the app falls back to
  `src/renderer/index.html` (a diagnostic placeholder).
- `vendor/upstream/src/chat/chat-dist.html` — unused artifact that the vendored
  pi-chat build still writes (gitignored).

## 主动吸收上游（可选，不是义务）

上游发新版**不会影响我们** ✓。想拿它的新东西时才执行下面几步 ✓，而且可以只拿一部分 ✓
（比如只要 `pi-chat/` 的新样式，不动 `bridge/`）：

```bash
git clone --depth 1 --branch <new-tag> --filter=blob:none --sparse <upstream> /tmp/upstream
git -C /tmp/upstream sparse-checkout set pi-chat bridge pi-mcp assets
diff -rq -x node_modules -x dist /tmp/upstream/pi-chat vendor/upstream/pi-chat   # 先看清差在哪
# 1. 按需拷入 pi-chat/ bridge/ pi-mcp/ assets/（可以只拷其中一部分）
# 2. pi-mcp 变了才需要重建 MCP bundle
npm run build:mcp
# 3. 重建 UI 产物
npm run build:renderer
# 4. 验证（关键：真窗口 + 真模型跑一遍日常流程）
npm run lint && npm run typecheck && npm test && npm run verify && npm run test:daily
# 5. 在“我们相对分叉点做过的改动”里记一笔，并按需更新上面的 provenance 表
```

第 4 步里的 `npm run test:daily` 不是可选项 ✓：上游改的是 UI，而我们的注入层靠少数几个
DOM 钩子定位 ✓ —— 只有行为级测试才能在“界面看着没问题、功能已经没了”时报警 ✓。
