## P0 — 安全

**1. preload 的 `invoke` 是万能通道（根因）**
```ts
invoke(channel: string, ...args: unknown[]) { return ipcRenderer.invoke(channel, ...args); }  // preload.ts:76
```
渲染层任何脚本都能调 `pi:read-agent-files`（拿 `auth.json` 明文密钥）、`pi:write-agent-files`（改写 `settings.json`/`models.json`/`APPEND_SYSTEM.md`，间接让 pi 加载恶意 package/扩展开关）、`pi:set-config`、`pi:open-file`、`pi:list-sessions`。
放大因素：三个窗口全部 `sandbox: false`（`main.ts:71/96/128`）；生成的聊天 HTML **没有 CSP**（实测 `vendor/upstream/pi-chat/dist/index.html` 无 CSP meta），且它是 `file://` 加载。pi-chat 的 markdown 用 `markdownit({html:false})`（`globals.ts:12`）挡住了一层，但 mermaid SVG / katex / 模型图标/文件名等 `innerHTML` 仍是不可信输入面（`enhance.ts:89/107`、`composer.ts:193`）。
修复：`const ALLOWED = new Set([...])` 白名单校验；改 `sandbox: true`（preload 只用 contextBridge/ipcRenderer，可兼容）；聊天窗口加 CSP（`default-src 'none'; script-src 'unsafe-inline'` 或 nonce）。

**2. cmd.exe 参数注入（实测复现）**
```
cmd.exe /d /s /c echo A & echo INJECTED   →   stdout: "A \r\nINJECTED\r\n"
```
Node 在 `shell:false` 下不转义 `&`。`rpc-client.ts:136` 把 `piPath + args` 拼给 `cmd.exe`，而 args 含：设置面板自由文本 `config.args`、以及渲染层可传的 `--session <path>`（`pi:switch-session` / `pi:open-session-window`，Windows 文件名允许 `&`）。→ 命令执行。
修复：解析 `.cmd` 真实目标（`pi.cmd` 内容拿 `node .../pi.js`）后直接 spawn node；或对每个 arg 走 cmd 元字符转义；优先探测 `pi.exe`。

**3. `shell.openPath` 任意路径**
`main.ts:402-406` 只补了相对路径，绝对路径直通 → `.exe/.bat/.lnk/.url` 直接执行、UNC 路径触发内网 SMB。`:593` 的 rewindDiff 同理。修复：限定在 `workspaceRoot` 内 + 扩展名白名单；URL 走 `shell.openExternal` 并校验 `http(s)`。

**4.（P1）密钥回传** `main.ts:220` 直接把 `auth.json` 原文返回给渲染层并在设置页 textarea 明文展示。修复：只回掩码，写入走单独通道、只写不回读。

## P1 — 功能缺陷（都是在用但坏了）

**5. 多窗口会话不隔离** — `openSessionWindow` 建了 `childSession`，但所有 `ipcMain.handle` 都闭包在**模块级 `chatSession`**（`main.ts:487-）。在子窗口打字 → 驱动主窗口的 agent，`childSession` 只被 `dispose()`。
修复：按 `event.sender.id` 路由到对应 session。

**6. 退不掉** — `main.ts:605` 菜单直接 `app.quit()`，`659` 的 close 拦截 `preventDefault()` 只依赖 `isQuiting`，该标志仅在托盘退出里设。→ 关闭窗口只是隐藏，进程常驻。修复：`click` 里先置 `isQuiting = true`，或统一用 `before-quit`。

**7. @file 补全 / 附件按钮** — pi-chat 发 `searchFiles`/`pickResource` 并等 `{type:"files",query,files}` / `{type:"pickedResources",paths}` 回包（`composer.ts:1586,1600`）；但 preload 的 `postMessage` 是 `ipcRenderer.invoke()` 且**丢弃返回值**，main 的 handler 却用 `return` 回。全仓库无任何地方发这两个包 → 静默失效（README 却宣称支持）。

**8. 拖拽文件** — `sidebar.ts:371` 发 `appendInput`，但 `preload.ts:17-46` 的 `typeToChannel` **没有这个 key** → 只 `console.warn`。且 `File.path` 在 Electron 32+ 已删除（本机 43.7.0），需 `webUtils.getPathForFile`。

**9. 托盘图标 + 关窗失联** — 实测 `dist-electron/win-unpacked/resources/app.asar` 内**没有** `build/icon.png`（`package.json` 的 `files` 未列 build/），`tray.ts:11` 落到 `createEmpty()` → 不可见托盘；再叠加 #6 的 hide-to-tray → 用户找不回窗口。

## P2 — 性能与资源（本机实测数据）

| 项 | 实测 | 说明 |
|---|---|---|
| 会话轮询 | 68 个 jsonl / 168MB（最大 21MB） | `sidebar.ts:358` 每 5s 调 `pi:list-sessions`；handler 对**每个文件** `readFileSync` + `split("\n")` 全量解析，且递归进 `traces/`。主进程同步阻塞 → 打字卡顿 |
| 临时 HTML | `%TEMP%` 13 个文件 / **50MB** | `main.ts:109` 每次启动/每个窗口写一份 5.7MB（=pi-chat 全量 bundle）且从不删除 |
| 文件搜索 | 你的仓库 134,579 文件 | `search-files` 用 `readdirSync/statSync` 同步递归 maxDepth 6，无 `fs.promises` → 冻结 UI |
| rpc 日志 | 固定 `%TEMP%/pi-standalone-rpc.log`，每行 stderr `appendFileSync` | 主进程阻塞 + 无限增长（含完整命令行/路径） |

其他：`rpc-client.ts:243` `request()` 无超时（pi 挂住 → pending 永久堆积、UI 无报错）；`rpc-client.ts:286` 用 `!proc.killed` 判断存活，进程已退出时 `killed` 仍为 `false` → 用**已回收 PID** 执行 `taskkill /T /F`，可能误杀无关进程（应判 `proc.exitCode === null`）；`chat-session.ts:68` 兜底 `"pi"` 在 Windows 上大概率 ENOENT（CreateProcess 不做 PATHEXT 展开）。

## P3 — 工程化不足

- **零测试 / 零 lint / 零 CI**：根目录无 `.github`、无 eslint/biome 配置，`package.json` 无 `test` 脚本。至少该覆盖 `normalizeSpawnTarget`、`parseBuiltin`、会话列表解析、`escJs`。
- **无用依赖进包**：`@earendil-works/pi-coding-agent` 在 `src/` 里**零 import**（pi 是子进程调用），却 129MB 被打进 asar（asar 55MB / exe 105MB）。移到 devDependencies。
- **上游不可复现**：`vendor/upstream` 是整仓拷贝（155 文件，连 `.github/workflows`、`test/`、`l10n`、`.vscode` 都在），**上游 commit 无任何记录**（仅 package.json 里 1.3.8）；`pi-chat/dist/index.html` 被 gitignore → 新克隆必须联网 `npm install` 才能出 UI。
- **配置无运行时校验**：`loadConfig` 直接 `{...DEFAULT_CONFIG, ...raw}`（`main.ts:33`），`SET_CONFIG` 接受任意 partial → 传字符串 `args` 会被 spread 成单字符数组，spawn 静默失败。
- **无单实例锁**：未用 `app.requestSingleInstanceLock()` → 双开并发写 `config.json`（后写覆盖）并抢同一 session 文件。
- **注入残点**：`chat-adapter.ts` 里 `JSON.stringify(config)` 未转义 `<`，`config.args`/`env` 含 `</script>` 可闭合脚本块（自伤型，但与 #1 叠加可变实弹）。
- **死代码/无效链路**：`main.ts:10` 导入的 `destroyTray` 从未调用（也没有 `before-quit` 清理临时文件/子进程）；`sessionsList` 推送链路（两处 typeToChannel）**无生产者**，纯靠 5s 轮询；`chat-adapter` 里 `${"" /* THEME_CSS... */}` 残渣；`chat-session` 内层 `handleMessage` 与外层同名遮蔽；`toggle-extension` 里 `candidates` 数组算完不用。
- **占位页自相矛盾**：`src/renderer/index.html` 的 CSP `default-src 'self'` 会拦掉它自己的内联 `<script>`，`status` 永远停在「检查中…」（改 hash/nonce 或外置脚本）。
