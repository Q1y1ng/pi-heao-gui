## 1.3.0 — 2026-09-19

> **勘误（2026-09-21 补记）**：本页的 `pi-heao-gui-1.3.0-source.zip` 其实是个改了后缀的 tar
> （Git Bash 的 GNU tar 会忽略 `-a`），Windows 自带解压器打不开它。要 1.3.0 的源码请 `git clone` 后切到
> `v1.3.0`，或直接用 [1.3.1 的源码包](https://github.com/Q1y1ng/pi-heao-gui/releases/tag/v1.3.1)。
> **两个安装包不受影响。**

### Added

- **窗口总览：一眼看清每个窗口在干什么。** 多开几个窗口之后，"谁在跑、谁在等你、谁闲着"此前只能从托盘菜单
  和标题栏拼出来。现在标题栏多一个格子图标：一份**只读**清单（等待回答 → 运行中 → 空闲，同组内最近活动的
  在前），每行写明窗口 / 会话名、状态、未读条数与多久之前，点一行就把那个窗口提到前台。
  它**不新增任何轮询、也没有新的观察** —— 用的都是主进程本来就有的状态（流式开始/结束、待处理请求、未读计数），
  变化时才推。面板加载时会主动取一次（此前推送过的状态，在脚本还没加载时是收不到的）。
  顺带修掉一处会让界面看起来像坏了的地方：dock 的 pi 终端要排队等另一个 pi 装完包时，现在会**先说一句**
  （"终端要等另一个 pi 启动完成"），而不是静默地什么都不出现。
- **多项目：把常用的目录存下来，一键切换。** 工作目录那一条点开就是**项目列表**（名字 + 路径，当前项目打勾），
  可以改名、可以从列表移出（**不会动目录**）、目录不在了就标灰；下面是"最近使用"与"添加项目…"。
  侧栏搜索框旁边多一个 **「项目 / 时间」** 分组开关，按项目分组时会话按它**运行时的目录**归位 ——
  会话头里记的就是那个目录，所以**开在子目录里的会话也归到它所属的项目**，嵌套项目优先于外层项目。
  项目的定义是 **一个目录 + 一个名字**，不是新容器：窗口仍然只有一个工作目录，会话、终端、git 面板、
  文件树全部沿用既有链路（切换项目 = 切工作目录，其余照旧跟随）。
- **「待你处理」：所有窗口正在等你回答的事，集中在一处。** pi 需要回答时（权限、确认、输入）应用本来就会响
  提示音 —— 但**响的是哪一件事、在哪个窗口**，没有任何地方能看到。现在标题栏多一个铃铛：有几件在等就显示几，
  点开是一份**跨窗口**的清单（每条写清是什么、哪个窗口/会话、等了多久），点一条就把提出它的窗口提到前台 ——
  回答仍然在**那个窗口**里做，答完条目自己消失。条目随会话生命周期收尾：窗口关闭、切换会话、pi 退出都会把它
  撤下来。子窗口现在用**同一份 host**（此前子窗口自带一份 `postToRenderer` 字面量，于是它的提问既不上榜、
  也不响提示音）。
- **正在跑的时候点「新建会话」，现在给你一个新窗口，而不是一句拒绝。** 此前会弹「请先停止 agent 再新建会话」
  —— 因为 pi 一个进程只有一个会话，运行中的回合不允许被换掉。但"这件事先跑着，我另开一件"正是多窗口存在的
  理由，所以现在忙碌的窗口把新会话开在**它自己的窗口**里，原回合继续跑。顺带把入口收敛成一个**共用函数**：
  侧栏按钮、标题栏「+」、命令面板走 IPC，而**文件 → 新建会话（Ctrl+N）与托盘 → 新建会话此前是死的** ——
  前者发出的 `newSessionShortcut` 事件无人接收，后者发到渲染层的消息类型根本不在投递表里，点了没有任何反应。
- **一键「新副本」：建一个 worktree，并在新窗口里开始一个会话。** 变更面板里选分支、点「＋ 新副本」，就会在
  仓库旁边建出 `仓库名-分支名` 的工作副本，并开一个**自己的窗口**（标题就是分支名）在其中启动 pi ——
  原窗口继续跑自己的事。这是"同一仓库并行推进两件事"缺的最后一块：切换与隔离早就有，缺的只是**分派**；
  而想要第二个工作副本的场合，正是当前窗口正忙的时候。工作副本放在仓库**旁边**而不是里面（放在里面就是
  自己树里的未跟踪内容，每次 `git status` 都会提到它）。
- **导入会话：导出有了另一半。** 侧栏「导入」选一个 `.jsonl`（别的机器、别的 profile 导出的会话），
  它就进会话列表、点开就是那段对话。检查的是 pi 自己的会话头（第一行必须是会话头，否则侧栏就会列出一堆垃圾）；
  跨机器时那个会话记录的**工作目录多半不在这台机器上** —— 这时只改会话头里的 `cwd` 指向当前工作目录，
  **对话本身逐字节不动**，并在提示里说清楚。落点用 pi 自己的目录命名（`--E--AI-repo--`，拿真实 profile 的
  目录核对过），同名不覆盖而是加序号 —— 同一个会话从另一个 profile 导出过来时文件名是一样的，覆盖等于把
  本机那份毁掉。

### Fixed

- **点开对话里的一条链接，不会再把这个应用本身替换掉。** 对话渲染的是模型写出来的内容，markdown-it 会把裸 URL
  变成真的 `<a href>`，而此前没有任何东西拦着它 —— 点击即让**窗口自己**导航到那个远端页面。这不只是丢界面：
  Electron 的 preload 会在窗口的**每一次**导航后重新注入，所以那个远端源会拿到 `window.pi`，而它的白名单里
  就有 `pi:term-input`（往活动终端写原始字节）与 `pi:fs-write`。CSP 拦不住这条路（`default-src` 不约束导航，
  `navigate-to` 从未在 Chromium 实现）。现在每个窗口只显示本应用自己装配的页面：`http(s)` / `mailto` 交给
  系统浏览器，`file:` 之类一律拒绝，且**不转交系统 shell**。判定本身是纯函数（15 条单测）。
- **agent 挂掉时，横幅会说为什么。** 此前只有一句 `Pi process exited (code 1). Click reload or send a message
  to restart.` —— 而 `code 1` 在 Windows 上恰好也是**强制结束**（应用自己关窗/重载走的是
  `taskkill /PID <pid> /T /F`）的样子，所以那个数字既不能行动、也不算证据；pi 真正的死因只留在
  `%TEMP%\pi-standalone-rpc.log` 里。现在 RPC 客户端留下 pi 最后的 6 行 stderr，横幅带上其中最后 3 行。
- **两个 pi 不再同时往同一个 agent 包里装包（"反复退出 code 1"的那个真因）。** pi 每次启动都会按
  `~/.pi/agent/settings.json` 执行 `npm install --prefix <agentDir>/npm`，而应用会在多处同时起 pi（聊天会话、
  终端坞、第二个窗口）—— **两个安装撞进同一个 prefix，在 Windows 上必输**：`npm warn tar TAR_ENTRY_ERROR
  ENOENT` → `npm error code ENOTEMPTY` → pi 退出 1，而且输掉的那个 prefix 可能被留在半残状态，之后每次启动都
  同样失败。现在按 profile 串行化：同一 prefix 同一时刻只允许一个启动占用，占用的那次**报告就绪即交棒**
  （就绪信号是"pi 回答了应用发出的第一个请求"，实测冷启动 +170 s 仍未就绪，所以占用最多 300 s）。
- **pi 在启动阶段挂掉，现在会自动重开一次，而不是让你自己点重载。** 一次失败隔 1.5 s 重试一次，且**只在
  "尚未就绪"时重试**：跑起来之后再死不算启动失败，第二次启动仍失败也照旧收手。失败两次后仍然保留原来的形状
  —— 会话留在窗口里、横幅说明原因、发一条消息或重载即恢复。
- **切工作副本不再等 pi 启动。** 面板里选另一个 worktree 时会重绑聊天会话（= 起一个 pi），而那条 IPC 此前是
  `await` 到底才回复的 —— 于是"选目录"要等新 pi 启动完。工作目录本身在回复前就已保存，git 面板/文件树/终端
  各自跟着它走，所以现在**先回复、会话在后台重绑**。
- **门禁不再把"窗口没在画"当成应用缺陷。** 两套 e2e 的抖动同源于此：Chromium 会节流被遮挡的窗口 —— 对比度门禁
  读到的是**冻结的过渡帧**（切主题必须通过设置窗口，它正好遮住聊天窗口）；daily 用 `innerText`（依赖布局）读
  同一个窗口，**连用户自己那条消息**都读成空，于是约一半运行误报"没有助手回复"。现在：对比度测量先断言主题
  已切到位、读数取**级联值**并正确处理 `color(srgb …)` 与半透明背景的逐层合成；需要看渲染结果的小节先把窗口
  提到前台；daily 改读 `textContent`，并以**应用自己在写的会话文件**为地面真值。
- **无障碍门禁不再"跨主题"判色。** 它此前留下过一条 3:1 的缺陷记录，而那两次读数其实是把**浅色**调色板的文字色
  配上了**暗色**主题的侧栏底色 —— 正好是 **3.10:1** 与 **1.11:1**，即主题切换中途取样的产物。同一规则实测：
  暗色 **7.06:1**、浅色 **5.58:1**。
- **日志里那条 `unknown msg type for renderer` 不再对每条正常消息都喊一遍。** 它原本挂在 `PI_DEBUG_WINDOW`
  判断的 else 分支上，于是**成功投递**的消息也被报成"未知类型"，正常使用时持续刷屏，把真正的问题埋掉。
- **与会话有关的检查不再靠"碰巧有会话"。** 归档/删除小节会把沙箱里的会话清掉，多窗口检查此前便因此 skip；
  现在 harness 按需**补种**自己那份会话再查。

## 安装

需要 **Windows 10 / 11（x64）**、**Node.js ≥ 22**，以及 `pi` CLI：

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

再准备至少一个 provider 的凭据（写在 `~/.pi/agent/auth.json`，或让应用带你在内置终端里登录）。
安装程序可自选目录，会自动创建桌面与开始菜单快捷方式；便携版免安装直接运行，但**不支持自更新**。

## 注意

- **本版仍未签名**：首次运行 Windows SmartScreen 会提示"已保护你的电脑"，
  点 **更多信息 → 仍要运行**；或先比对下方 SHA256。
- 已安装的 1.2.x 会在启动约 20 秒后自动检查并下载本版；**便携版需手动换包**。
